# Hakim Documentation

Hakim's documentation is intentionally small. Start with the path that matches what you are trying to do rather than reading every file.

## I want to use Hakim

1. **[README](../README.md)** — what Hakim is, who it helps, modes, capabilities, and the shortest install path.
2. **[Install Hakim](../core/hakim-skill/INSTALL.md)** — exact host-specific installation, inspection, and removal commands.
3. **[Supported Hosts](SUPPORTED_HOSTS.md)** — current host surfaces and compatibility boundaries.
4. **[Known Limitations](KNOWN_LIMITATIONS.md)** — beta limitations, lifecycle boundaries, and unsupported claims.

If you are using AI coding tools while still building your engineering intuition, the README is the intended starting point. Use the default `full` mode unless you have a reason to choose another mode; the installed `help` capability gives the exact syntax for your host.

Hakim deliberately preserves host-native differences. The architecture document explains why semantic parity matters more than identical implementation structure.
